## 1. What this system is

A personal research-and-paper-trading hub ("Research Desk" standard: visual, verdict-first, aggregate over lists). It combines:

- **Forecast journals** with frozen, graded predictions (oil, weather, macro, crypto, sports) scored against Kalshi and baselines with paired Brier statistics.
- **A Workshop** where strategy ideas are drafted (AI-assisted), backtested against a shuffle bar and an unseen-split claim check, and — only on a saved PASS plus live-forward evidence — promoted to tracking or live paper trading.
- **Two Alpaca paper books** traded by a scheduled runner: a ~$100k main book and a $1M book, with options support (defined-risk verticals as single multi-leg orders, covered calls, min-1-contract rule).
- **Desks and tools:** commodities/oil live page with a Chokepoints (Strait of Hormuz) monitor, a crypto valuation desk plus on-chain (Dune) data as a Workshop source, a screening engine with a natural-language translator, IPO/M&A deal builders, TradingAgents debate pages, and an in-site strategy agent (interpreter + accuracy gate; compiler/monitor/ledger still to build).

## 3. Working discipline (do not break what works)

- **Ship flow:** changes are pushed with a contents-API helper that opens and merges a PR in one step. Before shipping: full pytest (single invocation), full vitest (single invocation, `TMPDIR` pointed off the 512MB `/tmp` tmpfs or it ENOSPCs), `tsc --noEmit`, and `ruff check --select F` must show **no new errors** over the pre-existing baseline (9: 8× F401 + 1× F841 in `tradehub/journal/service.py` and tests). The gate must run on the **exact tree after the final edit** — follow-up edits invalidate it.
- **Back-to-back PRs touching the same files** from the same base can silently drop the earlier PR's hunks in shared files (happened twice, PRs #290/#296, repairs #291/#297/#298). After any such sequence, grep merged `main` for **both** PRs' markers in **every** shared file and run the full suites on merged main.
- **Rebuild the graphify graph before shipping** (repo `AGENTS.md`): `python -c "from graphify.watch import _rebuild_code; from pathlib import Path; _rebuild_code(Path('.'))"`. `graphify-out/` is gitignored generated output.
- **Kevin's presentation rules** (they are product requirements, not taste): aggregate first — totals, rates, verdict; per-item detail only on request or when one item needs his action. No infinite scrolling on any page; detail lives behind dropdowns. Pages lead with the biggest or live idea; never silently cut detail to shorten a page — move it behind a dropdown or onto its own page.
- **Options safety rules:** defined-risk verticals are placed as **one** multi-leg (mleg) order, never as separate legs (a separately-sent short leg reads as uncovered and is rejected — and the rejection must always create a visible manual-action notice; silence was the original defect). Covered calls get no min-1-contract rule; defined-risk verticals do (one contract's max loss must fit the idea's size budget, else a manual-action notice). **Closing** legs stay single-leg on the kill path by design.
- **Prediction integrity:** forecasts freeze before the event and are graded against settlement; model promotions (ens-v2.1, geo shadow) require ≥200 newly settled contracts and a paired-Brier win by >1 SE, and **Kevin decides** — nothing auto-promotes. Never present stale/last-known data as live (AIS ship data is flagged stale with its as-of time).

## 8. Known issues and latent risks — start the deep dive here

1. **Fail-soft endpoints can hide total failures.** PR #324 shipped `GET /api/oil/itm-record` calling an undefined `get_client()`; its fail-soft `except` branch served zeroes forever, indistinguishable from an empty record — and the full test suite passed because nothing exercised the endpoint's wiring. Fixed in #331 (client now injected via `Depends(get_supabase)`, plus a wiring regression test). **Audit every fail-soft endpoint for the same class**: a swallowed exception should be logged loudly server-side, and each public endpoint deserves one wiring test that proves its dependency actually reaches the business function.
2. **Ruff baseline drift:** the recorded baseline (9) silently became 10 when the F821 above landed — nobody re-checked between #324 and #331. Re-baseline after this fix and treat any count change as a stop.
3. **Stale-worktree shipping hazard:** shipping pushes file contents via the API from a worktree whose git HEAD may be far behind `main`. Any file edited from a stale copy can regress newer work. Prefer fresh worktrees off current `main` (fetch first — ship tooling does not use local refs).
4. **Namesake repo:** a from-memory slug once merged a stray PR into `kevinsigey/algo-trade-hub` (the real repo is `kevinsigey/algo-trade-hub-prod`). Kevin's decision on reverting that stray merge is **still open** — ask, don't assume. Always copy the slug from the shipping clone's `git remote -v`.
5. **Dune refresh is blocked:** Kevin's Dune account is read-only via API (cannot create/save queries) and its per-cycle datapoint limit is exhausted (HTTP 402), so the on-chain cache cannot refresh until the cycle resets or Kevin raises the limit (his subscription settings — never purchase anything). The five original stablecoin queries are unsaved/temp and the API refuses to execute them. A refresh script and a feed-creation script sit ready on the agent side.
6. **Single-leg short-add caveat:** when only a vertical's short leg needs opening while the long is already at target, the planner still emits a single-leg row; if Alpaca refuses it, the never-silent rule raises a manual action (visible, accepted) — but a proper covered-spread add path would be better.
7. **Tailscale persistence:** the VPS's userspace tailscaled dies on reboot, taking the agent's SSH route with it. Making it permanent needs a root-owned unit (Kevin/root task).
8. **Test-suite flakiness under load:** a handful of tests are timing/load-sensitive (App shell route-change, one Portfolio order test, Workshop draft fallback, CalibrationCurve, RequireAdmin menu, one exits time-budget test, a Portfolio treemap-label race). They pass solo; treat isolated failures under parallel load as suspects, not verdicts — but a deep dive that de-flakes them would pay off.
9. **Frontend test quirk:** components importing the workshop lib chain need the supabase module mocked; `String.replaceAll` is unavailable in the test/runtime target (use regex replace). The Oil page has a copy-budget test (60 words across h1/h2/h3/p/summary) — new Oil labels must use divs/spans/SVG text, not headings/paragraphs.
10. **CodeRabbit is rate-limited** on this repo; PRs have been merged on self-review with that stated in the PR body (Kevin's standing allowance). A deep dive should not mistake absent bot review for absent review — but should also re-check the PRs merged that way (#326–#331 especially).
